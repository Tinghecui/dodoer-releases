## 1. 问题

原来 `docs/host-choice.md`（#245）的做法是：整台服务器对「浏览器调用去哪台」「`ssh desktop` 去哪台」各只有一个答案。没固定时靠猜（开了 Chrome 开关的优先，其余看谁最近活跃），固定了就所有对话都用那一台。

2026-11-15 评审代码、和用户讨论之后，结论是这个模型本身不对：

- **答案是全局的。** 两台电脑上各跑一个对话，只能都去同一台。
- **「最近活跃」会被不相干的动作改掉。** 在另一台电脑上点一下窗口、切一下 Chrome 开关、断线重连，正在干活的智能体就可能中途换电脑。
- **用户最主要的用法正好撞上它。** 让智能体在家里的台式机上干活，人出门后用笔记本或手机看进度。「看」不能把活挪到笔记本上。
- **固定带来新问题。** 固定的那台不在怎么办、用完要记得改回来；评审里还确认了两个 bug（第 16 节）。
- **服务器只认得此刻连着的电脑。** 电脑一断线就从列表里消失，说不出「台式机上次在线是什么时候」。

## 2. 用户要的（2026-11-15）

1. 每台连过这台服务器的设备都记在服务器上。手机现在不用管（手机上还没有能被操作的东西），以后会出自己的手机客户端，要留位置。
2. 服务器知道：有哪些设备；每台的命令行、Chrome 现在能不能被操作；在线，还是上次在线是什么时候。
3. 看和操作分开：智能体在操作台式机时，用笔记本或手机打开同一个对话看，不受影响。
4. 换设备是人说了才换：在笔记本上说「先别用台式机，用笔记本」，之后再说「切回台式机」，都在笔记本上完成。
5. 人说「看一下我电脑上的文件」时，智能体知道这条消息是从哪台设备发来的，那台就是「我的电脑」。
6. 开始用设备时问一次；之后人换了设备，智能体做到一半不打断。

四个决定项：

| 问题 | 用户定的 |
|---|---|
| 设备的名字怎么来 | 第一次连接时问用户；跳过就用电脑名称 |
| 智能体没说在哪台设备上 | 每个对话开始用设备时确认一次，知道消息是从哪台发的就把那台排在前面；定了以后人换设备不打断 |
| 借出开关能不能远程操作 | 只能在那台电脑本机上开，可以远程关 |
| 人出门后电脑睡眠 | 借出期间不让电脑睡眠 |

不做的：

- 把手机当成被操作的设备。登记簿里留了类型，别的不做。
- 远程打开借出。
- 跟着发消息的设备自动换（用户否决：正是它让「出门看进度」把活挪走）。
- 定时任务无人值守地用设备（第 14 节）。
- Windows、Linux 桌面。

## 3. 三个词

- **设备**：登记簿里的一条，一台装了 CoTeam 的电脑。有编号（不变）和名字（人起的，`ssh` 用它）。
- **当前设备**：这条消息是从哪台设备发来的。只是信息：用来理解「我的电脑」、给确认卡片排序。它不决定智能体去哪台。
- **工作设备**：这个对话在操作的那台。定下来以后一直是它，直到人说换。2026-11-16 起分成两样（6.8）：
  - **命令行那台**：`ssh` 能去的那台；接口回答里的 `device`，存的字段沿用 `working`。
  - **浏览器那台**：`browser_open_tab` 不带 `device` 开在它上面；接口回答里的 `browserDevice`。
  两样可以是同一台，也可以各是一台，也可以有一样没选。下文说「工作设备」而没分的地方，指的是两样同一台的情况；分开以后哪一样按哪台查见 6.5、6.8。
- **确认过的设备**：人在 `use_device` 弹的卡片上点过的那几台。两样都能用它们（`scp -3` 那种同时用两台）。2026-11-20 起界面上选别的不再清空它们，只有「不用电脑」才清空（6.7）。
- **保留下来的旧电脑**（2026-11-20）：在设备按钮上换走的那台，按换走的那一样留下来，照样能用（6.7）。

## 4. 设备登记簿

### 4.1 记什么

| 字段 | 例子 | 从哪来 |
|---|---|---|
| 编号 | 32 位十六进制 | 桌面 app 第一次用到时随机生成，存在 `~/.codeg/device-id`（已有，`host_device.rs`） |
| 名字 | `desktop` | 用户起的，或电脑名称转成的（4.3） |
| 电脑名称 | `书房的 iMac` | 系统的「电脑名称」（已有） |
| 机型 | `iMac`、`MacBook Air` | 新增：「关于本机」里的机型名（`system_profiler SPHardwareDataType` 的 `machine_name`），英文。电脑名称转不成名字时用它 |
| 类型 | `desktop`、`laptop`；留着 `phone`、`tablet` | 新增：机型以 `MacBook` 开头的算笔记本，其余 Mac 算台式机。只用来显示图标 |
| 系统 | `macos` | 已有（`ShellHost.platform`），改成跟设备走 |
| app 版本 | `1.6.8` | 事件 socket 的 `hello` 里已经有 |
| 登录名 | | 借出命令行时报的（已有），记最后一次的 |
| 第一次连接、上次在线 | 时间 | 服务器记 |
| 被远程停止 | 是、否 | 第 7.2 节 |

不存下来、随连接变的：在线与否；命令行是「可用」「没借出」还是「已停止」；浏览器是「Chrome」「内置浏览器」「没借出」还是「已停止」；哪些对话正在用它。

### 4.2 什么时候登记，怎么算在线

- 桌面 app 的每个远端窗口，在服务器答了 `server_info` 之后发一次 `host_register`，带 `device`。现在就是这样，而且不管借没借出东西都发（能力可以是空的）。服务器收到就在登记簿里新建或更新这一条。所以只是用来看对话的笔记本也在表里。
- **在线** = 这台设备至少有一条事件 socket 连着。同一台设备的几个窗口算一台，借出的东西取并集（已有）。
- **上次在线**：最后一条 socket 断开时写；在线期间每 5 分钟写一次，服务器被强杀后这个时间也不会差太多。服务器刚启动时所有设备都是离线，等它们重连。
- 设备不会自己过期，要用户在面板里删。
- 不带 `device` 的连接（网页、现在的手机 app）不登记。以后的手机客户端带上 `device` 和类型 `phone` 就进表，表和接口不用改。

### 4.3 名字

- 规则：小写字母、数字、短横线，字母或数字开头，最多 32 个字符，一台服务器上不重复。
- **第一次连接时问**：这台设备的 app 在远端窗口里弹一次「给这台电脑起个名字」，输入框里先填好默认名字，「确定」或「跳过」。跳过就用默认名字。问之前设备已经用默认名字登记了，不耽误用。
- **默认名字**：先去掉电脑名称里「谁的」那一截（`James's MacBook Air`、`张三的MacBook Air` 都只看 `MacBook Air`），剩下的字母和数字留下并转成小写，其余换成短横线（→ `macbook-air`）。剩下不到两个字符（比如全中文的名称 `书房电脑`）就用机型的英文名做同样的事（`iMac` → `imac`），没有机型就用类型（`desktop`、`laptop`），再不行叫 `device`。重名时加 `-2`、`-3`。
- 服务器的 `~/.ssh/config` 里已经有同名的 `Host` 时不让用这个名字：我们的配置排在最前面，会盖住用户自己的。
- 任何设备上都能在面板里改名。改了以后 `ssh` 配置立刻重写，旧名字不再通；带着旧名字的标签编号（5.2）失效，重新列一次标签即可。工作设备按编号记，不受影响。
- 名字可能带人名（电脑名称转来的），和电脑名称一样不写进服务器日志，日志里只写编号的前 8 位（已有的规矩）。

### 4.4 存在哪儿

`app_metadata` 里两个键，都是 JSON：

- `host_devices.registry`：设备列表（4.1 的字段）。
- `host_devices.conversations`：每个对话的工作设备（命令行那台 `working`；浏览器单独选过时还有 `browser` 和 `browserApart`，见 6.8）、确认过的设备、最近一条消息来自哪台、哪一样在等人选（`wanted`、`browserWanted`）（第 6 节）。只留最近 500 个对话。

不新建数据库表：设备最多十几台，对话那一份是可以丢的缓存；不加迁移，测试包和正式包可以共用一个数据目录，也不和上游的迁移排顺序。

### 4.5 接口

`cowork::api_routes`，`server_info` 的 feature 是 `host_devices`：

- `POST /api/list_host_devices`：设备列表，带 4.1 里随连接变的那几项。
- `POST /api/rename_host_device`，`{"id", "name"}`。
- `POST /api/forget_host_device`，`{"id"}`：只能删不在线的。
- `POST /api/stop_host_device`，`{"id"}`：远程停止借出（7.2）。
- `POST /api/get_conversation_device`，`{"conversationId"}`：这个对话的工作设备和它现在的状态，给对话里的标记用（第 8 节）。回答里 `device` 是命令行那台、`needsPick` 是命令行那一样在等人选；有 feature `conversation_device_split` 的服务器多 `browserDevice`、`needsBrowserPick`（6.8）。
- `POST /api/set_conversation_device`，`{"conversationId","deviceId"|null,"part"?}`：在界面上选（6.7）；`part` 是 `"shell"` 或 `"browser"` 时只改那一样（6.8）。

`/api/get_host_devices`、`/api/set_host_choice` 和 feature `host_choice` 删掉（第 1 步）。老的桌面 app 看不到 `host_choice` 就不显示它的选择面板。

## 5. 按名字操作

### 5.1 SSH

`<数据目录>/host-ssh/config` 里一台登记过的设备一段，名字就是设备的名字：

```
# <id8> 是设备编号的前 8 位
Match originalhost desktop exec "printenv CODEG_CLI_CALLER >/dev/null"
  ControlPath <目录>/cm-<id8>-${CODEG_CLI_CALLER}
Host desktop
  HostName dodoer-<id8>
  HostKeyAlias dodoer-<id8>
  User <这台设备报的登录名>
  IdentityFile <目录>/id_ed25519
  IdentitiesOnly yes
  UserKnownHostsFile <目录>/known_hosts
  StrictHostKeyChecking yes
  ProxyCommand <codeg-cli 的绝对路径> desktop proxy --device <设备编号>
  ControlMaster auto
  ControlPath <目录>/cm-<id8>
  ControlPersist 10m
  ServerAliveInterval 30

Match originalhost laptop exec "printenv CODEG_CLI_CALLER >/dev/null"
  …
Host laptop
  …

Host *
```

- **每台设备自己的登录名、主机密钥、代理命令、共用连接。** 没有哪一段会因为「现在该去哪台」而被改写，所以不存在「配置写的是 A、连接留的是 B」。
- **什么时候重写**：登记簿变了（新设备、改名、删除），或者某台设备借出的命令行变了（主机密钥、登录名）。和谁最近活跃无关。
- 离线、没借出的设备也有一段。这样 `ssh laptop` 永远到得了代理命令，由它说清楚为什么连不上（5.3），而不是「找不到主机」。
- `known_hosts` 一台借出中的设备一行，名字是 `dodoer-<id8>`：一台设备只能出示它自己的密钥。
- **`codeg-cli desktop proxy --device <编号>`**：连 `GET /api/cli_host_tunnel?device=<编号>`，并带上它所在进程的 `CODEG_CLI_CALLER`（每个智能体进程和它跑的命令都有，值是连接编号）。服务器向这台设备借出命令行的那条 socket 要通道；同一台设备有几个窗口时用最近用的那个。
- **共用连接按对话分**（`Match` 那两行）：有 `CODEG_CLI_CALLER` 时，`ControlPath` 后面多带连接编号。不然对话 B 会顺着对话 A 留下的连接进去，服务器既拦不了它（6.5），也说不出是谁在用这台设备。没有这个变量时（人在服务器终端里自己敲 `ssh`）用一台设备一条的。2026-11-15 在服务器的 OpenSSH 9.6 上用 `ssh -G` 验过两种情况；`${}` 要 OpenSSH 8.4 以上。socket 路径超长时不分对话，退回一台设备一条。
- **限速改成每台设备各算**：现在全服务器每分钟最多 6 条通道（`TUNNELS_PER_MINUTE`），是为了不超过 CoTeam nginx 对一个来源地址每分钟 20 条新连接的限制。通道是设备拨过来的，每台设备是自己的地址。
- 密钥、`Include`、`Host *` 结尾这些照旧（`docs/host-ssh.md` 5.3）。

**老名字 `desktop`**：

- 有设备叫 `desktop`：就是它。
- 没有，而且只登记过一台设备：`desktop` 也指这一台（写在它那段的 `Host` 行上）。只有一台电脑的人，原来的 `ssh desktop` 不受影响。
- 没有，而且登记过几台：`ssh desktop` 失败，说明里列出各台的名字。

### 5.2 浏览器

- `browser_open_tab` 多一个可选参数 `device`（设备的名字）。没带就用这个对话的浏览器那台（6.8；两样同一台时就是工作设备）。带了的话，只能是浏览器那台或卡片上确认过的；只被选作命令行的那台不行，说明里写着这个对话的浏览器在哪台。
- 返回的标签编号前面带设备名：`laptop:3f2a…`。之后的读取、点按、导航、关闭都按编号里的名字找设备，不用再说在哪台。在台式机上开的标签，人换到笔记本上发消息之后照样够得着。
- `browser_list_tabs` 列出这个对话的浏览器那台和卡片上确认过的设备（第 6 节）上的标签，每个带设备名；只被选作命令行的那台不列。可选 `device` 只看一台。一台都没有时返回空列表，并记下「浏览器在等」，让用户在设备按钮上给浏览器选一台（6.7、6.8）。
- 网页在那台设备上开在 Chrome 还是内置浏览器，仍然由那台 app 自己定（「让智能体用我的 Chrome」开关）。`chrome` 这个能力只用来在设备列表里显示，不再参与选设备。
- 同一台设备开着几个远端窗口时，服务器记住每个标签是哪个窗口报上来的（内存里），找不到就问这台设备最近用的那个窗口。
- 改动的位置：加前缀、去前缀在 `RemoteHostBrowser`（`web/host_browser.rs`，第 3 步从 `web/host_registry.rs` 挪出来），按设备找 socket 在 `HostRegistry::route_tab`、`route_open` 里；工具定义（`acp/delegation/companion.rs`，上游文件）只加一个可选参数。`BrowserTabOp::Open` 多一个可选的 `device`，发给桌面端之前去掉。
- 要知道「是哪个对话在调」：`BrowserToolAccess` 的方法现在不带调用者，需要在分发的地方（`acp/delegation/listener.rs`，上游文件）多传一个连接编号。这是整套设计里对上游文件最大的一处改动。

### 5.3 用不了时说什么

哪种情况都不换到别的设备。说明是给智能体看的英文，下面是要点：

| 情况 | 说明里有什么 |
|---|---|
| 设备不在线 | 名字、上次在线的时间；让用户在那台电脑上打开 CoTeam |
| 在线，但没借出这一项 | 名字、没借出的是命令行还是浏览器；让用户在那台电脑上打开借出 |
| 被远程停止了 | 名字、是用户停的；只能在那台电脑上重新借出 |
| 这个对话还没确认过这台设备 | 让智能体调 `use_device`（6.5） |
| 没说设备，这个对话也没有工作设备 | 浏览器工具自己走确认（6.2） |
| 名字不认识 | 现有设备的名字 |
| 老名字 `desktop` 指不明 | 现有设备的名字 |
| 通道太多、设备拒绝、没拨回来 | 照旧 |

`cli_host_tunnel` 给每种情况不同的状态码。现在「固定的不在」和「没人借出」都是 503，说明丢了时代理只能猜；改完以后代理按状态码就知道是哪一种。

## 6. 工作设备：每个对话确认一次

### 6.1 当前设备怎么知道

桌面 app 替远端窗口转发请求时（`commands/remote_proxy.rs`），多带一个头 `X-Codeg-Device: <设备编号>`。服务器在收到用户消息（`/api/acp_prompt`）时，记下「这个对话最近一条消息来自哪台设备」。网页和手机发的消息没有这个头，记成「不知道」。

它只用在两处：确认卡片里把这台排在前面并标上「你现在用的这台」；`list_devices` 告诉智能体，让它听得懂「我的电脑」。

### 6.2 确认卡片

一个对话要操作一台它**没确认过**的设备时，先问人一次。卡片和 `ask_user_question` 的是同一种，标题是「这个对话要操作你的电脑，用哪台？」，选项是登记簿里的设备：

- 智能体提议了一台（人在消息里点了名，比如「去 desktop 上跑测试」）：这台排第一。
- 没提议：当前设备排第一。
- 当前设备标「你现在用的这台」；用不了的设备照样列出来，写明原因，不能选。

人点了哪台，哪台就是这个对话的工作设备，并记为「确认过」。答案可能和智能体提议的不一样，工具把人选的那台告诉智能体。

不问的情况：

- 登记簿里只有一台设备。直接用它，只有一台电脑的人永远看不到这张卡片。
- 这台设备在这个对话里确认过。

所以一个对话里，每台设备最多问一次。

### 6.3 中途换设备

工作设备定了以后，人换一台设备看对话、换一台设备发消息，都不变，也不弹卡片。智能体接着在原来那台上干。

只有一种情况要智能体自己判断：当前设备和工作设备不是同一台，而人的话指的是「这台电脑」「我手上这台」。这时它应该问一句。这条写在工具说明里，服务器拦不了。

### 6.4 切换

人在任何设备上说「换成 laptop」，智能体调 `use_device("laptop")`：

- 这个对话第一次用 laptop：弹一次卡片，点一下。
- 之后说「切回 desktop」「再换 laptop」：两台都确认过，不再弹，直接换。

第一版里切换只有「说」这一条路。对话里的标记只显示，不能点着换：点了以后智能体不知道，它还会接着用原来的名字（第 15 节）。6.7 起也可以在标记上点着选。

### 6.5 服务器怎么拦

确认不靠智能体自觉，服务器按对话检查：

- **浏览器**：`browser_open_tab` 要去的设备（参数里的，或工作设备）没确认过，或者两样都没有，这次调用自己弹卡片、等人答完再继续。其余工具按标签编号找到设备，同样检查。
- **SSH**：代理带来的 `CODEG_CLI_CALLER` 对得上一个对话，而这个对话没确认过这台设备，通道不开，立刻失败，说明让智能体去调 `use_device`。不在 `ssh` 里等人点卡片：命令会卡到超时。
- 没有 `CODEG_CLI_CALLER` 的（人在服务器终端里自己敲的）放行。
- 智能体委派出去的子对话，按最上面那个对话算。
- 两台都确认过以后，`scp -3 desktop:… laptop:…` 这样同时用两台是允许的。

检查的是「这个对话确认过这台设备没有」，不是「是不是当前的工作设备」。智能体在两台都确认过的设备之间用错了名字，服务器不拦；对话记录里每条命令都带着设备名，看得出来。

2026-11-16 起（6.8）按「哪一样选了哪台」分开查：

- **SSH**（`check_ssh`）：能连的只有命令行那台和卡片上确认过的。只被选作浏览器的那台被拒绝，说明里写着这个对话的命令行在哪台。命令行那一样没选时记下「命令行在等」，让用户去设备按钮上选。
- **浏览器**（`resolve`，`browser_open_tab` 和所有带标签编号的工具都走它）：能去的只有浏览器那台和卡片上确认过的。只被选作命令行的那台被拒绝，说明里写着这个对话的浏览器在哪台。浏览器那一样没选时记下「浏览器在等」，让用户在设备按钮上给浏览器选一台，不用 `ask_user_question` 问。
- 一样没选时不退到另一样选的那台，也不退到「唯一借出浏览器的那台」：拿不准就拒绝。`host_registry.rs` 的 `only_browser()` 只在没有对话、没有装 `DeviceTools` 时才走。
- 只有一台设备时什么都不问、不拒绝，和原来一样。
- 2026-11-20 起（用户定的，6.7）：命令行换走以后留下的旧电脑也能 `ssh`，浏览器换走以后留下的也能开网页，各算各的：只当过命令行的不因此能开网页，反过来也一样。从没在这个对话里选过、确认过的电脑照旧被拒绝，说明不变。

### 6.6 智能体的工具

codeg-mcp 多一个工具组「设备」（设置里和浏览器、电脑操作并排），取代 `docs/host-ssh.md` 5.5 里计划的 `desktop_shell_status`：

- `list_devices`：登记簿里的每台设备（名字、电脑名称、类型、系统、在线或上次在线、命令行和浏览器的状态、`ssh <名字>` 的用法），加上这个对话的工作设备、最近一条消息来自哪台。
- `use_device(name?)`：把这个对话的工作设备定为这台。没确认过就弹卡片（6.2）；不带名字就是「问用户」。返回人选的那台。

规矩写在这两个工具的说明里：操作用户的电脑之前先 `use_device`；人点了名就把名字传进去；工作设备定了就一直用它，消息从别的设备发来也不换；设备用不了就告诉用户，不换别的；删除、覆盖、改系统设置之前先问。

### 6.7 在界面上选（2026-11-15 第二轮）

用户：选哪台借出的电脑不该让智能体用 `ask_user_question` 来问，直接在 CoTeam 的会话界面上选。这一节改掉 6.2、6.4、6.5 里「智能体弹卡片」的部分，其余不变。

- **没选时**：

  - 两台以上：智能体要用设备（`use_device` 不带名字、`browser_open_tab` 不带 `device`、`ssh`）时**不弹卡片**，工具回答「用户还没在界面上给这个对话选电脑：请他用输入框下面的设备按钮选，选好再试；不要用 ask_user_question 问」。服务器同时给这个对话记下「等着选」，标记变成琥珀色的「选电脑」，直到选了为止。

- **换走以后**（2026-11-20，用户定的）：一个对话用过的电脑（在设备按钮上选过的、在确认卡片上点过的）一直可以用，已经开着的连接不断，新命令也能跑，直到：
  - 在那台电脑上停止借出、门户吊销、设备下线（沿用现有逻辑，用户要收回就靠这个，「只能靠停止借出那台设备」）；
  - 那台从设备列表里删掉；
  - 用户在设备按钮上点「不用电脑」：命令行、浏览器、卡片上确认过的、保留下来的旧电脑全部清空。
  换走的那台按换走的那一样保留：命令行换走的只保留命令行，浏览器换走的只保留浏览器（6.8 定过「一样没选时不退到另一样」，换走不该多放开一样）；不带 `part` 两样一起换的，两样都留。只把一样设成「不用」（`part` 带着、`deviceId` 为空）时，这一样一台都不用：它保留的旧电脑清掉，卡片上确认过的只留给另一样。`list_devices` 的回答另外列出这些还能用的旧电脑（名字和能用哪一样）。存在对话记录的 `keptShell`、`keptBrowser` 里，为空时不写；老记录没有这两个字段，读出来权限不变。设备按钮的菜单和标记不显示「这台还能用」。

- **智能体的工具说明**（`tool_schema.json` 的 `list_devices`、`use_device`、`browser_open_tab` 的 `device`，`list_devices` 的回答）：工作设备由用户在界面上选；没选时让用户去选，不要自己问；用户在对话里点了名才带名字调 `use_device`。

6.8 起，菜单分成命令行、浏览器两列，上面说的「选的那台成为工作设备」在只选一列时只换那一样；~~「确认过的设备换成只有它一台」改成「确认过的设备清空」，两列各自的选择就是这个对话能用的~~（2026-11-20 起不再清空，见上面「换走以后」）。

### 6.8 命令行和浏览器分开选（2026-11-16，#341）

用户（2026-11-16，看着输入框下面的设备标记）：「现在只能知道在使用哪台电脑的ssh借出但是不知道在使用哪台电脑的chrome」「在这个session实时显示 电脑正在被借出但是chrome 借出 状态也要显示」。当时对话选的那台只借出了命令行，Chrome 借出在另一台上：一个对话只能选一台，所以它其实用不了任何 Chrome，标记上又只写着一个名字，看不出来；想让命令行走一台、浏览器走另一台也做不到。

本机会话给了两个做法：「分开选」和「还是一台，只把浏览器用不了显示清楚」。用户看过能点的样子后定了**分开选**，标记两样都写，并且实时显示借出状态和正在用的状态（Chrome 那一样也要）。理由：人手里常是一台借了命令行、另一台开着 Chrome，只能选一台就总有一样用不了；只显示清楚还是解决不了。

- **记什么**：每个对话记命令行那台（`working`）、浏览器那台（`browser`，`browserApart` 为真时才算数）和卡片上确认过的。老记录（只有 `working`、没有 `browserApart`）读出来两样都是 `working`，`confirmed` 不变；所以升级以后已经选了的电脑不丢，也不多出权限。`browserApart` 为真而 `browser` 为空，就是用户明确选了浏览器不用。两样又选回同一台时存回老的样子。
- **接口**：`set_conversation_device` 多一个可选的 `part`：`"shell"` 只改命令行那台，`"browser"` 只改浏览器那台，另一样不动；不带 `part` 和原来一样两样都改（`null` 就是两样都不用）。~~任何一次界面上的选择都清空卡片上确认过的。~~ 2026-11-20 起（用户定的）界面上选一台不再清空卡片上确认过的，换走的那台按那一样保留，只有「不用电脑」全部清空（6.7「换走以后」）。回答里 `device` 还是命令行那台（老界面读它，意思不变），新加 `browserDevice`、`needsBrowserPick`。`server_info` 多 feature `conversation_device_split`。
- **在等**：两样各记各的（`wanted`、`browserWanted`）：命令行选了、浏览器没选而智能体要开网页，是很常见的情况。
- **怎么拦**：6.5 末尾。
- **`use_device(name)`**（人在对话里点名换）：两样一起换到这台，这台进确认过的。「换成 laptop」说的是整台电脑；要分开只能在界面的菜单上选，不给 `use_device` 加 `part`，智能体不能自己把两样分开。不带名字时回答两样各是哪台。
- **给智能体看的文字**：`list_devices` 在两样同一台时还是「This conversation works on `X`…」；不同台时分别写命令行在哪台（`ssh <名字>`）、浏览器在哪台（`browser_open_tab` 不带 `device` 就开在那台）；某一样没选时说哪一样没选、让用户去设备按钮上选。结构化部分多浏览器那台的名字、每台设备多「是不是浏览器那台」。拒绝的说明分命令行、浏览器两种。
- **设备面板的「正在用它的对话」**：命令行或浏览器选的是这台都算，面板上不分两样显示。
- **菜单**（有 `conversation_device_split` 时）：一台一行（名字、电脑名称、「这台」、在线或上次在线），右边「命令行」「浏览器」两列各一个单选圈；浏览器那一格下面写开网页用的是 Chrome 还是内置浏览器。点一个圈只改那一样，菜单不关，好接着选另一列。那台没借出这一样、不在线、被远程停止时那一格不出圈、写原因、点不了；正是现在选着的照样显示选中的圈，旁边用琥珀色写原因。最下面「不用电脑」两样都清掉。
- **标记**：见第 8 节。
- **老服务器**（没有 `conversation_device_split`）：标记和菜单和 6.7 一样。

放弃的：

- **还是一台，只把浏览器用不了显示清楚**：看得出问题，但解决不了「命令行走这台、浏览器走那台」。
- **一样没选时退到另一样那台，或退到唯一借出浏览器的那台**：用户只给了一样，另一样不该跟着放开。
- **`use_device` 加 `part`**：分开是人在界面上的决定，不让智能体自己分。

## 7. 借出：本机开，远程可关，借出期间不睡眠

### 7.1 本机开（不变）

借出命令行的开关只在那台电脑的 CoTeam 里，打开时每次都确认（`docs/host-ssh.md` 5.4）。出门之后靠得住的条件已经具备：借出按服务器记在 app 里，app 重启后跟着远端窗口恢复；远端窗口在 app 启动时自己重开；app 可以设成开机启动。

### 7.2 远程停止

设备面板里每台在线的设备有一个「停止借出」，在任何设备、网页上都能点。点了以后：

1. 服务器立刻把这台设备记为「已停止」（存进登记簿）：不再往它那里发调用和通道，正开着的通道马上断。
2. 服务器给这台设备的每条 socket 发 `host_stop`。新版 app 收到后关掉对这台服务器的命令行借出（从 `host_ssh.lent_servers` 里去掉），不再向这台服务器报浏览器和 Chrome，并在窗口里提示「已从别的设备停止借出」。
3. 恢复只能在那台电脑上：在借出面板里重新打开（照常弹确认）。app 重新登记时带一个「人在本机重新打开了」的标记，服务器才清掉「已停止」。

不认识 `host_stop` 的老 app 会接着报它借出了什么，服务器不理，继续拒绝，面板里写「要在那台电脑上更新 CoTeam 后重新借出」。

停止是把所有借出一起停。智能体失控、人又不在电脑前时，要的是一下全断。

### 7.3 借出期间不睡眠

命令行借给至少一台服务器期间，app 起一个 `/usr/bin/caffeinate -s -w <dodoer 的进程号>`：系统不进入睡眠，屏幕照常熄灭。借出关了就结束它；CoTeam 退出或被强杀，它自己结束（`-w`）。

- `-s` 只在接着电源时有效。笔记本用电池时照常睡。
- 笔记本合上盖子照样睡，系统不让改。
- 只跟命令行的借出开关走，不跟浏览器：浏览器工具的开关本机的智能体也在用，很多人一直开着，跟着它的话只要开着远端窗口电脑就永远不睡。
- 借出面板里写一行「借出期间这台电脑不会睡眠（接着电源时）」。

## 8. 界面

- **设备面板**：侧栏底部那个「两块屏幕」的图标（`status-bar-devices.tsx`，原来的 `status-bar-host-choice.tsx`），点开从两个「固定」下拉框换成设备列表。一台一行：名字、电脑名称、「这台」、在线或「上次在线 …」、命令行和浏览器的状态、正在用它的对话。可以改名、停止借出、删除（不在线的）。网页和桌面 app 的远端窗口里都有。
- **对话里的标记**：输入框旁边一个小标记「desktop」，这个对话有工作设备时才出现。那台设备用不了时变琥珀色，悬停说明原因。6.7 起它是按钮，点开在界面上选工作设备；没选时写「选电脑」，智能体等着用设备时变琥珀色。6.8 起（服务器有 `conversation_device_split` 时）标记两样都写：
  - 两样同一台：电脑图标 + 名字，后面跟命令行和浏览器两个小图标；不同台：命令行图标 + 名字，浏览器图标 + 名字。浏览器图标在那台借出的是 Chrome 时用 Chrome 的，否则用地球。
  - 只选了一样：另一样的图标后面写灰色的「没选」；智能体在等这一样（`needsPick` / `needsBrowserPick`）时这一半变琥珀色、带闪的点。
  - **用不了**：某一样选的那台不在线、被远程停止、或没借出这一样时，这一半变琥珀色，名字换成原因（「没借出」「不在线」「已停止」），悬停写是哪台、为什么、怎么办（在那台电脑上打开借出）；另一半不受影响。借出状态跟着每 10 秒一次的查询变。
  - **正在用**：智能体正在用某一样、而且是这台电脑的（`useSessionUsage`，`docs/session-usage-badge.md`）时，这一半变成天蓝色（和对话标题旁边的标记同一个颜色）、带闪的点；用完变回灰色（命令行是连接一断，浏览器是最后一次调用之后约 30 秒）。和「用不了」同时成立时显示「用不了」。
  - 放不下时名字截断、图标保留，悬停写全。
- **确认卡片**：6.2。
- **起名**：4.3，在设备自己的远端窗口里弹一次。
- **借出面板**（`status-bar-host-ssh.tsx`）：多两行，「借出期间这台电脑不会睡眠」和被远程停止时的「已从别的设备停止，重新借出」。
- 文字在 `src/lib/cowork/i18n.ts`（英、简、繁）。

手机 app 里暂时没有这些界面。设备列表可以直接问智能体，切换本来就是说一句。

## 10. 兼容

- **新服务器，老桌面 app（带 `device`，1.6.6 起）**：能登记、能被点名操作；没有起名的弹框（用默认名字，可以在面板里改）；不带 `X-Codeg-Device`，当前设备是「不知道」；不认识 `host_stop`（7.2）。
- **新服务器，更老的桌面 app（不带 `device`）**：不进登记簿。只有它一台连着时照老规矩当 `desktop` 用；有登记过的设备时不再用它，面板里提示更新。
- **老服务器，新桌面 app**：多出来的字段和头被忽略，和现在一样。没有 `host_devices` 就不显示设备面板和起名。
- 服务器从带 `host_choice` 的版本升上来：存着的固定选择不再读，留在 `app_metadata` 里不删。

## 11. 安全

- **同意分两层**：设备那一层是借出开关，只能在本机打开；对话那一层是确认卡片，一个对话动一台设备之前要人点一次。服务器或智能体都不能替人做其中任何一层。
- **远程只能收紧**：停止借出谁有服务器的令牌都能点，重新借出只认那台设备的 app 在本机操作之后发来的标记。app 不会因为服务器的任何消息而打开借出。
- **当前设备不是凭据**：`X-Codeg-Device` 谁有令牌都能随便填，但它只影响卡片里谁排第一，换不来任何权限。
- **名字只是称呼**：通道和调用按设备编号走；名字写进 `ssh` 配置前按 4.3 的规则检查，写不进别的指令。
- 日志里只有设备编号的前 8 位，没有名字、电脑名称、登录名。
- 其余和 `docs/host-ssh.md` 第 6 节一样：借出 = 把这个账号的全部权限交给服务器上的智能体。

## 12. 分步

每步一个 PR，Rust 只在 CI 上编。合并后自动发版；生产服务器的升级另外找用户确认（重启会断一下对话）。

| 步 | 做什么 | 做完能验什么 |
|---|---|---|
| 1 | 登记簿、`device` 多带的字段、4.5 的接口、设备面板、起名、改名、删除；去掉「固定」和它的接口、界面 | 两台 Mac 都出现在面板里，名字对，在线和上次在线对，重启服务器后还在 |
| 2 | SSH 按名字：一台设备一段配置、`desktop proxy --device`、5.3 的说明、每台设备各自限速；去掉命令行的自动 | 服务器终端里 `ssh desktop hostname`、`ssh laptop hostname` 各到各的；一台退出后另一台不受影响，说明写得对 |
| 3 | 浏览器按名字：`browser_open_tab` 的 `device`、标签编号带设备名；去掉浏览器的自动 | 智能体分别在两台上开网页；在另一台上点窗口、切 Chrome 开关都不影响 |
| 4 | 工作设备：`list_devices`、`use_device`、确认卡片、当前设备、对话里的标记、SSH 按对话分连接和检查 | 第 13 节的 4～8 |
| 5 | 远程停止借出、借出期间不睡眠、「正在使用」 | 第 13 节的 9、10 |
| 6 | 更新 `COWORK.md`、`docs/host-ssh.md`、`docs/remote-browser.md`；两台 Mac 完整验收 | |

「固定」放在第 1 步就去掉：它是用户否决的做法；生产服务器 2026-11-15 已经是带着它的 v0.6.7，但库里没有任何固定记录（`host_choice.choices`），去掉不丢东西。旧 app 看服务器不再报 `host_choice` 就不显示固定的界面。第 1 步之后、第 2、3 步之前，浏览器和命令行仍按原来的自动规则选电脑（开了 Chrome 开关的优先，其余看最近活跃）。

第 2、3 步合并之后、第 4 步之前，智能体可以直接按名字连，没有确认卡片。这段时间服务器上只有用户自己在用。

## 13. 验收

两台 Mac，下面叫 `desktop`（台式机）和 `laptop`（笔记本），服务器和两台的 app 都是新版。

1. **登记**：两台第一次连上时各弹一次起名；一台填名字，一台跳过（得到电脑名称转成的名字）。面板里两台都在。退出 `laptop` 的 CoTeam，它显示「上次在线」和时间。重启服务器，列表还在。
2. **改名**：把跳过的那台改成 `laptop`，`ssh laptop hostname` 立刻能用，旧名字不通。
3. **按名字**：服务器终端里 `ssh desktop hostname` 和 `ssh laptop hostname` 是两台不同的电脑；两条同时跑互不影响。
4. **开始时确认**：在 `laptop` 上新开对话说「看一下我电脑上的下载文件夹」。卡片出现，`laptop` 排第一并标着「你现在用的这台」。点它，命令在 `laptop` 上跑。
5. **点名**：新对话说「去 desktop 上看看磁盘空间」。卡片里 `desktop` 排第一。
6. **看不影响干**：让一个对话在 `desktop` 上跑一个要几分钟的命令。在 `laptop` 上打开这个对话，点窗口、切 Chrome 开关、发一条「到哪了」。之后的命令仍然在 `desktop` 上，没有卡片。
7. **切换**：在 `laptop` 上说「换成 laptop」，弹一次卡片，之后在 `laptop` 上跑。说「切回 desktop」，不弹，回到 `desktop`。对话里的标记跟着变。
8. **拦得住**：新对话里让智能体直接跑 `ssh desktop true`，失败，说明让它调 `use_device`；确认后同一条命令成功。
9. **用不了**：退出 `desktop` 的 CoTeam，`ssh desktop` 的说明里有名字和上次在线的时间，`laptop` 上什么都没发生。重新打开、关掉借出，说明变成「在线，没借出命令行」。
10. **远程停止**：`desktop` 上开着一个 `ssh` 会话，在 `laptop` 的面板里点「停止借出」，会话几秒内断开，`desktop` 的借出开关变成关。在 `laptop` 上找不到重新打开的地方。回到 `desktop` 重新借出，恢复。
11. **不睡眠**：`desktop` 借出期间 `pmset -g assertions` 里有 `caffeinate`，放着不动不睡；关掉借出后没有了。
12. **浏览器**：让智能体在 `desktop` 和 `laptop` 上各开一个网页，标签编号带着各自的名字；人在 `laptop` 上发消息时，智能体读 `desktop` 上那个标签照样成功。
13. **手机**：在手机上给一个没有工作设备的对话发「看一下磁盘空间」，卡片列出两台，没有「你现在用的这台」。
14. **只有一台设备的服务器**：没有卡片，`ssh desktop` 和现在一样。
15. **新老搭配**：第 10 节的三种组合都不报错。

## 14. 局限

- 定时任务里没人点卡片。无人值守的对话第一次用设备会停在确认上；以后给自动化加「预先指定设备」。
- ~~工作设备只能说着换，界面上不能点着换。~~ 6.7 起可以在界面上选。
- 命令行和浏览器只能在界面上分开选（6.8）；对话里点名换（`use_device`）总是两样一起换。
- 卡片上确认过的设备两样都能用：`use_device` 换过去的那台，命令行和浏览器都放开。
- 智能体在两台都确认过的设备之间用错名字，服务器不拦。
- 共用连接的 socket 路径超长时不分对话，这时 6.5 只拦得住开连接的那个对话。
- 笔记本合上盖子就离线。
- 远程停止对老 app 只在服务器这一侧生效，那台电脑上的开关看着还开着。
- 确认卡片要在 `use_device` 的处理里向人发一个和 `ask_user_question` 一样的问题并等回答，这段在上游的 `acp/delegation` 里。第 4 步如果接不进去，退一步：工具返回「要先问用户」，由智能体自己调 `ask_user_question`，再带着答案调 `use_device`。那样服务器拦得住「没选过」，拦不住「没问就选」。

## 15. 放弃或推后的方案

- **自动 + 固定（#245）**：第 1 节。
- **跟着发消息的设备自动换**：2026-11-15 提给用户，被否决。出门后用笔记本看进度、回一句话，活就被挪到笔记本上。发消息的设备现在只是「当前设备」，用来排序和理解「我的电脑」。
- **按机型自动起名 `desktop`、`laptop`**：用户选了第一次连接时问、跳过用电脑名称。
- **设一台「默认设备」**：又是一个全局设置，设过就忘。
- **有几台可用时只报错，让智能体自己去问**：问不问全看智能体读没读说明。改成服务器按对话检查、自己弹卡片。
- **每次调用都问**：太烦。一个对话里一台设备问一次。
- **界面上点一下就切换**：智能体不知道换了，会接着用原来的名字。要做就得把「换了」作为一条消息送进对话，推后。6.7 换了个做法：界面上选的作废之前的确认，旧名字被服务器拦下、说明里写着新的，不用往对话里塞消息。2026-11-20 起用户改成界面上选的只是默认去处，旧名字不再被拦（6.7「换走以后」）：不点名的调用去新的那台，`list_devices` 先写新的。
- **新建数据库表**：4.4。
- **远程也能打开借出**：能登录服务器的人就能把电脑借给自己，本机同意这一层就没有了。
- **只在服务器上拒绝、不通知 app 的远程停止**：那台电脑上看着还借着，人回来不知道被停过。两边都做。
- **`ssh` 里等人点卡片**：命令会卡到智能体的超时。改成立刻失败，让智能体去调会等人的工具。
- **在设备按钮上换走就断开旧电脑的连接（PR #1031，已关）**：换走后几秒内断开到旧电脑的连接，收回得最干净，但正在跑的命令会被打断。2026-11-20 用户要的是「换设备还在旧的设备上继续跑」，改成设备按钮只决定默认去哪台（6.7「换走以后」）。同时放弃的还有「让正在跑的命令跑完、但不让发新命令」：智能体想回旧电脑接着干会被拒绝。

## 16. 评审 #245 时发现的问题在这里怎么了

| 问题 | 在这里 |
|---|---|
| 固定的那台不在、另一台的共用连接还活着时，`ssh desktop` 顺着旧连接进了另一台 | 不会出现。每台设备自己一段配置和连接，名字到设备的对应不随在线情况变 |
| 固定的不在、又没有别的电脑借出时，说明是「请打开桌面 app」而不是「固定的那台不在」 | 说明按 5.3 重写，每种情况带名字 |
| 503 的说明丢了时，代理把「固定的不在」猜成「没人借出」 | 每种情况自己的状态码 |
| 重新注册（包括切 Chrome 开关）会刷新「最近活跃」，自动模式下 `ssh desktop` 中途换电脑 | 不会出现。「最近活跃」不再用来选设备 |
